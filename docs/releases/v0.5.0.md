# 滚猫md v0.5.0

v0.5.0 加入 TextPack 支持。Markdown 正文与本地图片可以保存在同一个 `.textpack` 文件中，移动和发送文档时一起携带。

## 打开、编辑与保存

- 使用“打开”选择 TextPack；Windows 也支持拖入窗口和通过启动参数打开。
- 从“更多”选择“新建 TextPack”，可直接创建内置附件的文档并插入图片。
- TextPack 保持所见即所得、源码、阅读三种视图。点击“保存”更新整个文件；普通“另存为”继续保存 TextPack。
- 将现有 Markdown 转成单文件文档：打开 Markdown，从“更多”选择“另存为 TextPack”，选择目标位置。可访问的本地图片随正文打包，网络图片保留原网址。
- 在 TextPack 内粘贴截图或使用“插入本地图片”，图片加入包内附件，手动保存后写入文件。图片以原始二进制内容存储，无需 Base64。
- 本机恢复草稿同时保留 TextPack 正文和附件。草稿仍最多保留 5 份；原文件由用户手动保存。
- 桌面二进制保存沿用普通文本保存的授权检查和原子替换流程。

## 网页图文粘贴

从网页复制文字和图片后，可直接粘贴到编辑区。应用将剪贴板 HTML 转为 Markdown，保留主要内容顺序、标题、列表和基础文字样式，并尝试下载可访问的 HTTPS 图片。

TextPack 文档将成功下载的图片存入包内。空白、未保存的文档在成功包含网页图片后自动采用 TextPack；已有普通 Markdown 文档在原生版中使用旁置 `assets/` 文件夹。图片下载失败时保留可见的 Markdown 链接，正文仍可继续编辑。

每次最多下载 32 张图片，每张最多 8 MiB、合计最多 32 MiB，仅下载 HTTPS 图片；浏览器还受来源服务器的 CORS 策略限制。剪贴板须提供 HTML，复杂网页布局会转换成基本 Markdown 结构。

## 格式与平台边界

- TextPack 使用 ZIP 容器，包含 Markdown 正文、`info.json` 和图片附件。普通 `.md` 的保存方式继续适用；普通 Markdown 跨目录另存时需自行复制外部附件。
- 支持 PNG、JPEG、GIF 和 WebP，每张最多 32 MiB。压缩包大小与解压后总大小分别最多 128 MiB，最多 4,096 个条目。
- 当前不直接打开 `.textbundle` 文件夹。加密、ZIP64、不支持的压缩方式和损坏的包会报错；路径和大小校验在打开包时执行。
- Android 系统文件选择器支持 `.textpack`。从系统 URI 导入后，第一次保存需要选择导出位置。将普通 Markdown 与图片转换为 TextPack 前，需先通过“关联图片文件夹”取得相应权限；读取包内图片无需旁边的图片目录。
- Android 的直接“打开方式”匹配取决于来源应用提供的 MIME 信息；被识别为通用 ZIP 的 `.textpack` 可从应用内文件选择器打开。应用不注册通用 ZIP 文件关联。
- 浏览器版可读取 TextPack 包内图片。浏览器直接打开普通 `.md` 不会取得旁边图片目录的权限，请使用原生版完成这类文档的图文打包。
- 浏览器保存回退为下载时，应用无法确认文件已落盘，会保留当前文档状态及未保存提示。取消或失败时，原文档继续保留。
- 普通 Markdown 转换为 TextPack 时，现有网络图片保留原网址；网页图文粘贴会尝试内置成功下载的图片。离线时能否显示取决于图片是否已经内置。TextPack 正文仍须使用 UTF-8；其他编辑器需要支持 TextPack 才能直接编辑，也可先用 ZIP 工具解压正文和附件。

## English

v0.5.0 adds TextPack support. Markdown and local images can travel together in a single `.textpack` file.

Open TextPack from the file picker, by dropping it onto the Windows app, or as a startup file. WYSIWYG, Source, and Reader remain available. **Save** updates the package, and regular **Save As** retains its format. To convert an ordinary Markdown document, choose **More → Save As TextPack**. Accessible local images are included; remote images keep their URLs.

Choose **More → New TextPack** to start directly with embedded attachments. Pasting web text and images converts clipboard HTML into Markdown, retaining the main order, headings, lists, and basic styles. Downloaded images are embedded in TextPack or saved in the adjacent `assets/` folder for ordinary Markdown in the native app. A blank unsaved document switches to TextPack when web images are successfully included. Failed downloads leave visible Markdown links. Each paste downloads up to 32 HTTPS images, at most 8 MiB each and 32 MiB total; browsers remain subject to CORS.

Pasting or inserting an image into a TextPack adds its original binary content to the package. Saving writes the complete document and attachments. Recovery drafts retain both text and package attachments, within the existing five-draft limit. Desktop package saves share the text save path's authorization and atomic replacement behavior.

TextPack is a ZIP container with Markdown, `info.json`, and attachments. PNG, JPEG, GIF, and WebP are supported up to 32 MiB each. Compressed and total uncompressed sizes are each limited to 128 MiB, with up to 4,096 entries. `.textbundle` directories, encrypted archives, ZIP64, unsupported compression methods, and damaged packages are unsupported. Markdown must use UTF-8. Other editors need TextPack support for direct editing; a ZIP tool can extract the text and attachments.

Android document imports require an export destination on the first save. Converting an ordinary Markdown document with sibling images requires a linked image folder. Embedded TextPack images need no sibling-folder permission. External **Open with** availability depends on the source app's MIME type; use the in-app picker when a provider identifies TextPack as a generic ZIP. No generic ZIP association is registered.

The browser build displays embedded package images. Use the native app to bundle sibling images for ordinary Markdown documents, since opening a `.md` in a browser does not grant access to its neighboring folders. When saving falls back to a browser download, the app cannot confirm persistence and retains the current document state and unsaved indicator. Remote images still need a network connection unless already embedded.

Validation on 2026-09-08 passed 229 frontend tests, 11 Rust tests, 13 browser round-trip/recovery checks, 3 real Ctrl+C/Ctrl+V checks, and 5 asynchronous paste/conversion checks. Browser checks use real editor DOM and IndexedDB with fixture image responses and mocked file interfaces. Windows EXE and signed ARM64 APK builds succeeded. Android reports version 0.5.0 / code 5000 and uses the previous release certificate; its packaged native library matches this build. The Android CLI's symlink permission failure was handled by copying the compiled library and packaging with Gradle while skipping the already completed Rust task. Native Windows UI and Android device flows remain untested. The table above records artifact sizes and SHA-256 values; see the [QA checklist](../qa-v0.5.0.md) for precise coverage.
